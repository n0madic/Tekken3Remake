# Tekken 3 remake (Godot 4.7, GDScript)

The plan, architecture and decisions are in [docs/remake-plan.md](../docs/remake-plan.md); the game's behaviour is specified by [docs/research](../docs/research/README.md).

## Setup

The repository's `Makefile` wraps the steps below and the builds (`make help`: `convert`, `import`, `run`, `test`, `test-quick`, `test-converter`, `export`, `export-<platform>[-full|-nomovies|-lite]`, `serve-web`, `clean-export`).

1. **Convert the disc.** The converted data is the single copy of the game assets, written to `remake/imported/`. It is git-ignored; builds that contain it must not be published. `manifest.json` records the converter version; a build refuses a folder written by another version (the game asks for a new conversion). Music and movies need FFmpeg: the first one on the `PATH` with the Theora and Vorbis encoders is used (`--ffmpeg PATH` picks one), else music is converted to WAV and movies to JPEG frames. `--no-music` / `--no-movies` skip them.

   ```sh
   python3 tools/remake_import/convert.py --image <disc image> [--image <disc image>] [--no-music] [--no-movies] [--arcade <tekken3.zip>]
   ```

   The discs are the images given with `--image` (a `.cue`, `.chd`, or data track `.bin`/`.ecm`/`.iso`), one per release; the converter tells the releases apart itself. Any one release is enough: the game is converted from Japan Rev.1 if given, else the original Japanese disc (SLPS-01300), else USA. The data of the other releases is rebased onto Japan Rev.1's addresses with the layouts in `tools/remake_import/layouts/` (`layout.py`). With a Japanese disc the USA disc is optional: given too, the English game texts also get the USA release's names, titles, staff roll, move lists and pictures with text (`imported/usa/`); the generic English menu wording is part of the project either way. Converted from the USA disc alone the game texts are English only (`manifest.json` `source`). `--arcade` adds the arcade version's stages 0–12 from MAME's `tekken3` ROM set (World ver. E1, a `.zip`; `tools/remake_import/arcade.py`): its polygonal scenery, tiled sky and floor (`imported/stages/<letter>/arcade/`, manifest group `arcade`), drawn instead of the PlayStation's flat panoramas by default (the Stage backdrops setting). It also replaces the character models of costume slots 0–40 (all but Mokujin's) with the arcade's (`arcade_character.py`): about 15 % more triangles and seams weighed across up to three joints, the same texture artwork, and the arcade's own swinging attachments (hair, sashes, skirts, tails) moved by its dynamics (`presentation/fighter/arcade_attachments.gd`, with the helicopter stage's wind); the skeleton, motions and everything the fight computes stay the PlayStation's.

2. **Golden traces (for tests).** These are written to `work/traces/` from the research work tree (`python3 tools/research/extract_work.py` first): pose traces, the attract demonstration, the costume attachments and whole fights run in the CPU harness; the whole game from boot (the flow traces: menus, every mode, practice, options, the attract loop) comes from `flow_trace.py`.

   ```sh
   python3 tools/research/export_traces.py
   python3 tools/research/flow_trace.py [scenario ...] [--jobs 4]
   ```

3. **Tests.** Headless, with the project's own runner (`tests/run_tests.gd`). Suites whose inputs are missing are skipped. The whole run (about three minutes; Tekken Force's long traces take most of it) is shared by parallel runners that take the longest tests first by the times of the last runs (`remake/.godot/test_times.txt`; `JOBS=<n>` sets the number of runners). `--quick` leaves out the comparisons with the game's traces (suites with `const SLOW := true`) and takes about 10 s; a run with a name filter uses one runner.

   ```sh
   tools/remake/run_tests.sh [--quick] [name filter]
   ```

4. **Run.** Open `remake/` in Godot 4.7, or run `godot --path remake`.
   - The main scene (`app/game.tscn`) is the whole game from boot: `NAMCO PRESENTS.`, the opening movies, the title and the attract loop (the demonstration and the demonstration fight), the main menu, options (records, memory card on a local file, key configuration), character select, arcade (ladder, continue, challenger, the Ogre scene and True Ogre, the ending and staff roll), VS, team battle, time attack, survival, practice, Tekken Ball (with its quick select and HOW TO page), Tekken Force (its levels, bosses, the Doctor B. level and its result), the results and the ranking with name entry, and Theater. The screens use the game's own pictures and fonts in the 368 × 480 layout.
   - Progress (the save block and the records) is kept in `user://progress.json`, or `progress2.json` with the setting Memory card on slot 2 (`app/progress_card.gd`; switching reloads the progress and reopens the main menu): loaded at the first title screen, saved by AUTO SAVE and by MEMORY CARD's CARD SAVE. AUTO SAVE starts on for a card with no save (off with `--fresh`), and leaving OPTIONS saves while it is on (or was on in the file, so turning it off lasts); the game itself would keep changed options until its next auto save.
   - Controls: each pad (on a button, its stick or a trigger), and each of the keyboard's two layouts, joins on its first press; the keyboard layouts take their own side when it is free: player 1 (left) W A S D + R T / F G (LP RP / LK RK, as Square Triangle / Cross Circle on the pad; Z X C V the shoulders, Space Start, Q Select), player 2 (right) the arrows + U I / J K (O P L ; the shoulders, Enter Start, Backspace Select); these are the defaults: the settings' Controls tab rebinds both layouts (Escape, Tab and F3 stay reserved; a key must report its physical position). ✕ and ○ (the keyboard's F and G, J and K) also skip what Start skips: the start-up, the attract sequence, a fight's replay and the movies. Esc belongs to the keyboard's player (else player 1; in a fight the human's when the keyboard's player does not play there) and joins no one: the pause in a fight, a movie skip and a move list's exit (Start), out of an open pause menu as CANCEL or practice's OK, and back in the menus: Select in the options and Theater, Start + Select, the game's way back to the main menu, on the character selects. Android's Back (button or gesture) does what Esc does, except on the main menu, where it does nothing; the application stays open. A tap or click is player 1's Start (in a fight the human's, and nothing while its pause is open). A fight pauses by itself when the window loses focus or the app goes to the background (as the human's Start would; in the round intro, as soon as the fight starts).
   - F3 shows frame rate and step timings.
   - **Settings** (the remake's own, `user://settings.json`): Select on the main menu (Esc, Q or Backspace; a click or tap on the gear at the top left, right of the left macro buttons on touch screens, where the touch controls hide while the settings are open), in two tabs (L1 / R1, Tab or a click): General and Controls, each in two columns on landscape windows. They are saved when the screen closes. Gameplay fixes (the original's gameplay bugs fixed, from the next mode), game texts (English: the USA release's wording, else the Japanese release's), interface language (English, Japanese; English only on the web, which has no CJK font), graphics preset (Auto, or the renderer's: Web; Standard and High on phones and tablets; Low and High on desktop), textures (smooth or crisp), shading (Original: the game's own normals; Smooth, the default: the fighters' normals averaged where faces meet; Smooth + curved: their triangles also drawn as curved PN patches), texture pack, frame interpolation, what fills the window beyond the scene, stage backdrops (Arcade, the default when the arcade stages were converted: the arcade's scenery, sky and floor; PlayStation: the home version's panoramas; from the next stage), four volumes, vibration (pads' motors; with the touch controls the phone's), touch controls (auto on touch screens), their macro buttons and their size (70–130 %), and the keys of the two keyboard layouts: a pad picture per player (the game's own KEY CONFIGURATION picture) with a field beside each button; Cross, Enter or a click on a field takes the next key (a key another button has swaps with it, Esc cancels), Default keys restores both layouts; on phones and tablets they are shown only with a keyboard attached (reported by the system, or one that pressed a key). Settings with a single choice in this build (a texture pack when none is installed) are not shown; a volume is set by a tap or a drag along its bar.
   - **Touch**: a stick where the left thumb lands, the four face buttons on the right, L1 L2 over the stick and R2 R1 over the face buttons in one row (only those the game's KEY CONFIGURATION gives an action: none by default; all four on that page, to give them one), Select and Start at the bottom in the middle, and macro buttons in the top corners; over movies, the title, the demonstration, replays and the records pages only Select and Start stay (1+3 and 2+4, or also 1+2 and 3+4); they are player 1's device.
   - **Texture packs**: `user://texture_packs/<name>/` with a `pack.json` and `<key>.png` pictures replacing the converted ones (fighters, panoramas, floors, tile maps, the HUD, effect flipbooks, screen pictures) at any resolution; 2D pictures keep their size and draw finer. A pack's `vram.json` and `vram/` replace sprites the 2D screens cut from VRAM (by texture page, texel rectangle and CLUT colours, only while VRAM holds the words they were made for). `python3 tools/remake/texture_pack.py dump <dir>` writes the originals under their keys (with `names.txt`), `check <dir>` checks a pack, `import-duckstation <DuckStation pack folder> <pack folder> --image <disc> ...` converts a DuckStation texture replacement pack (page-mode `texpage-*.png`; the same `--image` arguments as the installed conversion, which it repeats to record where each picture's texels come from in VRAM; needs `xxhash`; replacements the remake does not draw are listed in the pack's `import_report.txt`). Packs made from the originals or from an emulator pack contain game data: keep them private.
   - Options after `--` (on the web as the page's query string, `?speed=4&no-movies`): `--no-movies` plays as a build without movies, `--speed=<n>` runs n steps per tick, `--seed=<n>` fixes the random generators, `--fresh` starts from a fresh memory card and never reads or writes the save file, `--unlock` opens every character, Start costume, mode and Theater movie for the session (Tekken Ball, Theater, Gon, Doctor B., …) without saving that: the file keeps its unlock state and arcade clears (clears made during the session are not recorded), while the rest of the progress (records, statistics, options) is saved as usual, `--texture-pack=<name or folder>` uses an installed texture pack, or a pack's folder (any argument with a `/`), for the session, `--graphics=<preset>` a graphics preset of the renderer in use (`desktop_low`, `desktop_high`, …; another is ignored) for the session, `--shading=<original|smooth|curved>` a shading likewise (these three leave the saved setting unchanged; the settings screen shows the session's choice, and any choice there ends it), `--stats` shows the frame rate, the GPU time of the frames (also logged once a second; Godot's Metal driver measures none: add `--rendering-driver vulkan` before `--`) and the step timings, `--screenshot=<path> --frames=<n>` saves a frame and quits (`--frames` defaults to 90; drawn at that step, not interpolated, so screenshots repeat exactly; also with the window hidden or covered), `--m0` opens the M0 character viewer (`--slot=<n>` the move, `--yaw=<n>` `--pitch=<n>` `--distance=<n>` the camera, `--costume=<key>`: character · 4 + costume, `--hand=<value>[,<value 1>]` holds both hand channels at a channel value (or channel 0 at the first and channel 1 at the second): 0 open, 0x200 fist, 0x201 and up shapes, decimal or `0x` hex; the jaw of Kuma, Panda and Gon is channel 0), `--gaze=<shift>` holds Gon's eyes' look direction (−17 to 17), `--stages` the stage viewer (`app/stage_viewer.tscn`, no simulation: a free camera around the fighters' midpoint with the backdrop's turn set by hand; PageUp/PageDown or `,` `.` the stage, B Arcade/PlayStation backdrops, arrows the camera's yaw and distance, W S height, R F pitch, Q E the turn, Shift ×8, Space sweeps; `--stage=<0-14>`, `--yaw=<n>`, `--turn=<n>`, `--distance=<n>`, `--height=<n>`, `--pitch=<n>`, `--sweep`, `--backdrops=<arcade|playstation>`, `--screenshot=<path> --frames=<n>`), `--fight` the M2 VS set-up (`app/fight.tscn`: `--chars=<a>,<b>`, `--costumes=<a>,<b>`, `--stage=<0-14>`, `--fixes`, `--start`, `--autoplay` starts fights by itself and presses random buttons for both players, one match after another, `--quit-after-match` quits when the match is over). For development: `--replay=<scenario>` plays a flow trace's pads with its seed from a fresh memory card that is never written to the save file (compare a screen with `tools/research/gpu_raster.py`; `--replay-frames=<n>` stops it after n steps), `--pads=<file>` then plays a pad script (lines `<steps> <pad 1 hex> [<pad 2 hex>]`), `--screen=theater` / `--screen=ending[:<costume key>]` / `--screen=enbu[:<0-2>]` opens the Theater, an ending (Paul's by default) or an attract demonstration (the first by default, locked ones too).

## Layout

| Folder | Content |
|---|---|
| `core/` | Deterministic simulation, integer arithmetic, no nodes (`math/`, `fighter/`, `combat/`, `camera/`, `ai/`, `effects/`, `scripted/`, `fight/`, `force/`: Tekken Force's level runner, `ball/`: Tekken Ball, `game/`: the game's states, screens and modes). |
| `content/` | Loaders and data classes for the converted assets; `TextLocale` and `texts_en.json`: the English game texts. |
| `presentation/` | Views: fighters (seam-exact GPU skinning, hand variants, eyes), stages (panoramas, tile panoramas, spotlight floors) and lighting, effects (the effect objects from the game's own page and models), the camera rig, the HUD (with the Force and Ball HUDs, touch controls, button glyphs), Tekken Force's items, Tekken Ball's ball and court, the 2D screens and fades, the settings screen, the movie player, audio; the graphics presets (`render_quality.gd`) and texture packs. |
| `platform/` | Assets catalog (`Assets`), input router (`Pads`, with the touch device), settings (`Settings`), rumble. |
| `app/` | Scenes: the game (`game.tscn`: `GameFlow` with its views, audio, movies, the save file and the settings), the M2 VS set-up (`fight.tscn`), the M0 viewer; `SkipButtons` (✕ and ○ as Start); `translations.csv` (the remake's own interface in English and Japanese). The application icon is converted from the disc (`imported/icon.png`, the title's logo, with Android's adaptive layers); every build takes it, the web page's favicon included. |
| `dev/` | Development tooling, left out of exports: the golden traces' location (`TraceFiles`) and the flow trace reader the tests and `--replay` use. |
| `tests/` | `TestSuite` suites and the runner. |

## Exports

`export_presets.cfg` has a **full**, a **nomovies** (music, no movies) and a **lite** (neither) preset for macOS, Windows, Linux, the web (single-threaded, Compatibility renderer), Android (arm64, Mobile renderer) and iOS (an Xcode project to sign and build with your team). Desktop builds keep the large movies, the others the small ones. `tools/remake/export_all.sh [preset …]` exports them into `remake/export/` and prints each build's size; Android builds are signed with the keystore in `GODOT_ANDROID_KEYSTORE_RELEASE_PATH` / `_USER` / `_PASSWORD` (Godot's debug keystore by default). All builds contain converted game data and stay private.

```sh
tools/remake/export_all.sh "Web lite"
```

The web build waits for a click or key before it starts, so that the browser lets it play sound.
