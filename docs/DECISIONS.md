| D16 | Локальный сетевой VS: lockstep-нетплей поверх ENet. Autoload `platform/net_play.gd` (порт 31313), аргументы `--host[=порт]`/`--join=<ip>[:порт]` (и пункты меню NET MODE, D17); сервер шлёт seed (CMD_INIT→CMD_ACK), обе стороны пересобирают flow с общим seed, обмен GO, затем обмен pad-словами за `кадр+3` по надёжному каналу 0 (пакеты `[CMD_INPUT=0, кадр, слово]` — префикс, чтобы кадры 1–3 не коллидировали с командами; первые DELAY кадров префилл нулями); кадр шагает только при обоих словах (input delay 3 кадра, без rollback); бит Escape (ремейковское закрытие меню паузы) передаётся в кадрах `[CMD_INPUT, кадр, слово, esc]`/`CMD_ESC`, чтобы пауза снималась синхронно). Сервер = игрок 1 (бесконечное ожидание), клиент = игрок 2 (таймаут 15 с → офлайн); обрыв — сообщение и офлайн-продолжение (физика включается безусловно). **При соединении обе стороны сразу входят в VS MODE** (`_start_net_vs()` → `ModeStart.start(flow, GameMode.VS, 3)`), минуя титул/меню. Лаунчеры `netplay\1-сервер.bat`, `2-клиент.bat`. Автотест (16.11): два exe по 127.0.0.1 — идентичный select (hash PNG), бой на обеих сторонах | Пожелание пользователя: «сетевой режим, только локальный, один клиент, другой сервер — классика»; «при успешном соединении… автоматически переходить в vs mode, хост player 1, клиент player 2» |
| D17 | Пункт «NET MODE» в главном меню (перед OPTION MODE): весь функционал сети в игре. Новое состояние `GameFlow.State.NET = 20`, экран `core/game/net_menu.gd` + отрисовка `presentation/screens/net_view.gd` в стиле опций (фон и шрифты 0/1 из игровых ассетов; цвет пункта меню 9 — лист цвета 3 в шрифтах пуст), пересборка flow при подключении в `game.gd::_physics_process`, ввод IP через `_unhandled_input` → `NetPlay.type_char`. Пункт вставляется программно в `game.gd::_load()` (как D14); `--host`/`--join` остаются запасным путём | Пожелание пользователя: «в меню игры должен быть пункт NET MODE, весь функционал туда»; «перерисуй в стиле игры, шрифты из игровых ассетов» |
| D18 | Пункт «EXIT» в главном меню (после OPTION MODE): `GameFlow.quit_requested` → `game.gd::_quit()` (чистый выход: настройки, звук, вибрация). Вставляется программно в `_load()`, цвет 9 | Пожелание пользователя: «добавить в меню EXIT, который закрывает игру» |
| D19 | **REPLAY «Повтор последнего боя»** (пункт меню mode 13): `platform/last_replay.gd`, формат T3RP **v2** — seed + boot-прогресс 0x218 байт + 2 pad-слова/шаг + флаг блокировки роликом на шагах 0/1/2; воспроизведение через `flow.showing_fight()` с fast-forward 8×; отмена Esc/Select-edge; `_boot_progress` восстанавливает состояние на момент боя; `_on_movie_finished` нейтрализован для LastReplay; ветка harness instant-end исключает LastReplay. Юнит-тесты: 31 passed | Пожелание пользователя: «повтор последнего боя» как на приставке. Реализовано 16.11; пользователь выявил «при заходе в replay перезапускается игра» — исправлено (v2-формат, per-step флаги роликов, boot-прогресс); ручная проверка пользователем — отложена («оставим на потом») |
| D20 | **Splash-загадка решена**: причина показа лого Godot — строки-комментарии `#` в `project.godot` непосредственно перед `boot_splash/image`: экспортный шаблон читает следующий за комментарием параметр как **пустую строку** (без ошибки в лог) → тихий откат на дефолтное лого. Комментарии убраны из `remake\project.godot` и из `game\project.godot`. Формат дистрибуции: каталог `game\` (exe + распакованное содержимое pck + текстовый `project.godot`, без `project.binary`/pck). Загрузка PNG в экспортном шаблоне проверена отдельным тест-проектом — работает | Пользователь: «опять godot engine выходит»; «пусть игра выглядит так: папка с игрой, в ней exe и содержимое pck» |

Движковый boot splash отключён (`boot_splash/show_image=false`) — при загрузке проекта чёрный экран. Причина отказа от движкового splash: нет ни уменьшения, ни виньетки, ни затемнения | Пожелание пользователя: «барельеф много места занимает — уменьшить + виньетка, 3 секунды, затем смена кадра с затуханием» |
| D22 | **Порт на прошитую Nintendo Switch отклонён как неперспективный** (исследование 17.11.2026): homebrew-портов Godot 4 под Switch нет (Godot 3-порты мертвы: без звука/сети; RAWRLAB — только для зарегистрированных у Nintendo студий с SDK); рабочий путь был бы через switchroot Linux + экспорт arm64 + рендер `gl_compatibility` (пресет «web» уже предусмотрен), но производительность Tegra X1 на этой игре под вопросом, а трудозатраты несопоставимы | Пользователь: «можешь собрать для прошитого Switch?» → вывод «неперспективно» |
