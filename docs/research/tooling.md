# Research tooling

All tools read the user's own disc images. Extracted game data is written only to `work/` (research) and `remake/imported/` (the remake's converted assets, [remake-plan.md](../remake-plan.md#content-pipeline)); both are git-ignored and never published.

## Extraction

```sh
python3 tools/research/extract_work.py
```

Creates `work/<release>/exe.bin`, `work/<release>/bns/<id>_<original name>` and `manifest.json` for `jp_orig` (ECM read virtually), `jp_rev1` and `usa`. Filenames come from the original Japanese index.

## Ghidra (static analysis)

Ghidra 12.1.4 with the [`ghidra_psx_ldr`](https://github.com/lab313ru/ghidra_psx_ldr) extension (build with `GHIDRA_INSTALL_DIR=… sh ./gradlew buildExtension` after `git submodule update --init data/psyq`; install the zip into the user Extensions directory; `JAVA_HOME` must point to JDK 21). PsyQ signatures name 929 library functions.

```sh
python3 tools/research/make_overlay_exes.py            # EXE + overlay images at 0x800B0A10 / 0x800B9378
work/ghidra/run_overlays.sh                      # import/analyze each overlay program
work/ghidra/import_usa.sh                        # USA executable as program SLUS_004.02
python3 tools/research/make_overlay_exes.py --release usa
work/ghidra/run_usa_overlays.sh                  # the USA overlays whose code differs (practice, volley,
                                                 # title, ranking, ending)
analyzeHeadless work/ghidra/proj T3 -process -noanalysis -scriptPath tools/ghidra \
    -postScript ExportDecomp.java work/decomp     # decompiled C + function lists
```

| Script | Purpose |
|---|---|
| `tools/ghidra/ExportDecomp.java` | `<program>.c` and `<program>.functions.tsv`. |
| `tools/ghidra/ExportCop2Sites.java` | Addresses of COP2 instructions, including words inside multi-word GTE macro instructions. |
| `tools/ghidra/ApplyAnnotations.java` | Applies [`tekken3.h`](../../tools/ghidra/tekken3.h) types and [`symbols.txt`](../../tools/ghidra/symbols.txt) names/prototypes/comments to every program; `func@word` entries apply only to programs whose name contains `word`. |
| `tools/ghidra/gen_structs.py` | Generates the `Fighter` struct in `tekken3.h` and the field table in [code/fighter.md](code/fighter.md) from `fighter_fields.tsv`. |
| `tools/ghidra/label_funcs.py` | Turns code labels whose address is taken (callbacks, behaviour pointers) into function directives. |
| `tools/ghidra/RefunctionRange.java` | Rebuilds the functions of an overlay's own address range and writes `<program>.overlay.c`. It clears the range, seeds functions at stack-frame prologues (`addiu sp, −N` followed by `sw ra`) and at resident `jal` targets that start with such a prologue, follows the code flow, and adds `jal` targets found in that code until nothing new appears. Needed because resident code calls fixed entry points of every mode overlay (inherited bogus starts), and because screen overlays are mostly data (`select.ovl` has 20 functions in 460 KB). A prologue a few words after a call target is merged into that function, extra entry points reached only through computed jumps come from `tools/ghidra/overlay_seeds.txt`, and `analyzeChanges` recovers jump tables (switch statements). The decompiler is restarted after a failure. `work/ghidra/refunction_overlays.sh` runs it for all ten overlays in about a minute. |

`work/ghidra/annotate_all.sh` runs `label_funcs.py`, applies all annotations and re-exports the decompiled C (`sh work/fn.sh <addr>` prints one function).

## CPU/GTE harness

[`tools/research/psxcpu.py`](../../tools/research/psxcpu.py) executes individual game functions: Unicorn supplies the MIPS I core; a Python model of the GTE (all commands, FIFOs, saturation, UNR division as documented by [psx-spx](https://psx-spx.consoledev.net/geometrytransformationenginegte/)) handles COP2 instructions, which are replaced by NOPs at the addresses listed by Ghidra and emulated from code hooks. Unlisted COP2 instructions are caught lazily: the interrupt hook emulates the instruction, stops the emulation, and the site's hook and NOP are put in place outside Unicorn (`PsxCpu.defer`) before it resumes. Code that drives the emulation itself therefore calls `PsxCpu.run(pc)`, not `uc.emu_start`, which would end at the first such stop. Only data words that Ghidra has disassembled are patched — scanning the whole image for COP2 opcodes corrupts data tables (it broke the spline tables before this rule was adopted).

```python
from psxcpu import load_release
cpu = load_release()                 # or load_release(overlay="select")
cpu.write(0x80150000, data)
cpu.call(0x80035138, 0x80150000, 27, fighter)   # KmdRelocate
```

Unicorn follows QEMU for `div` by zero (the quotient is the dividend), while the R3000 returns −1 for a non-negative and +1 for a negative dividend (`divu`: all ones; `HI` = dividend). Ports follow the R3000. `PsxCpu.r3000_divide(site)` / `r3000_divide_range(lo, hi)` patch the result in the harness after each listed `div`, so the camera and Tekken Ball verifiers compare zero-divisor inputs too. When an overlay replaces the code, `drop_divides(lo, hi)` forgets its sites; their hooks stay and do nothing, as for COP2.

There is no GPU, SPU, CD-ROM, BIOS or interrupt model; functions that touch hardware must be stubbed (`cpu.stub(addr, fn)`).

**Fight harness.** [`tools/research/fight_harness.py`](../../tools/research/fight_harness.py) runs whole VS matches in the game's own `FightMain` with two bots on the pads (16 scenarios covering every character and stage, the round-flow cases and the options) and records, per frame, the pads, both fighter records, the engine calls (sounds, vibration, music, effects, shakes) and the RAM ranges of the round flow, camera, HUD bars and random generators (`fight_<scenario>.bin`, format in `write_trace`). Conventions shared with the remake: the display buffer is the frame counter's parity and the video frame count `0x800AE6E0` equals the frame counter (one vblank per frame); the bank table is recorded per stretch of frames (Mokujin reloads his bank each round). Presentation bugs the remake fixes (#1, #53, #54, #55, #58) are patched in RAM. The drawing routines are stubbed, except that `StageBackgroundDraw` is replaced by its only stateful part, the panorama's turn (`PANORAMA_TURN_ONLY`: `FUN_8006E4A0` added to `0x800A9650`). `FightHarness(gameplay_fixes=True)` also patches the Gameplay fixes (#7, #8, #52 as code, #9 as a Python replacement of `SegmentHitsCylinder`) and counts in the trace header (`fix_hits`) how often a fix changed a value; the `fixes_<scenario>` traces are the same matches with them. `python3 tools/research/export_traces.py --banks --enbu --attachments 0 --fight [names]` exports them (8 in parallel, about 18 minutes for all 32).

**Game harness and flow traces.** [`tools/research/game_harness.py`](../../tools/research/game_harness.py) runs the whole game from boot (every game state's handler, the overlays loaded into their slots as the loader asks) and [`tools/research/flow_trace.py`](../../tools/research/flow_trace.py) drives it with scripted pads (`Scenario`: the menus, character select, the modes, practice's pause menu; bots fight, and hold still while a pause menu is up) and records per frame the pads, the game state, the engine calls and the RAM ranges of the screens (`flow_<scenario>.bin`; `--jobs 1` runs in this process, so an emulator crash shows instead of hanging the pool). Harness conventions: movies end on their first frame, loading takes no time, the music is ready at once, a memory card has no file and saves succeed. `select.ovl`'s portrait TIM upload is skipped, and `force.ovl`'s target switch saves and restores the right angles (game-bugs #47, which the remake does not reproduce; `OVERLAY_PATCHES`). The `ogre` scenario keeps the CPU's health at one point while a round runs (`drain`, in the trace header), so that the bot climbs the arcade ladder through the Ogre scene and True Ogre; it ends as the ending starts, whose movie player crashes Unicorn. Tekken Force's scenarios play with `ForceBot` (it walks while no enemy is out, else fights) and refill the player's health, and the round timer when it runs low (`refill`, listed in the trace header for the test), so that the bot reaches the later levels. An overlay is loaded from its stub's hook only after the stub returns (`PsxCpu.defer`): the emulation stops, the COP2 sites of the replaced code are forgotten (`drop_cop2`: their hooks stay and do nothing, since translated blocks keep pointers to their hooks and deleting one crashed Unicorn) and the new ones added outside Unicorn, and the code is copied into place by a word loop the emulated CPU runs (`PsxCpu._copy_code`, beyond the 2 MB of RAM), so its stores invalidate the stale translated blocks as self-modifying code does. Host writes (`mem_write`) leave those blocks in place (execution at PC 0), and flushing the translation cache instead (`ctl_flush_tb`, `ctl_remove_cache`, inside or outside hooks) crashed Unicorn a few overlay swaps later.

**GPU reference pictures.** [`tools/research/gpu_raster.py`](../../tools/research/gpu_raster.py) `<scenario> <frames…> --out <dir>` runs a flow scenario and draws the frame's 2D ordering table (`0x800A96E0`) as a 368 × 480 picture: polygons, lines, tiles and sprites with the four semi-transparency modes, draw mode, draw area and offset, on the VRAM the remake builds (system textures and the screen's TIMs). For the pictures it puts back libgpu's packet setters the harness stubs (`SetDrawMode`, `SetDrawArea`, … and `GetDrawMode`'s helpers) and clears the table each frame as the main loop does. The remake's `--replay=<scenario>` option plays the same scenario's pads and seed, so a screen can be compared side by side with its reference (pictures uploaded outside the scenario's overlays, such as the portraits, are missing from the reference).

**Remake-side tools.** `remake/tests/support/fight_debug.gd` runs a scenario to a frame and prints simulation fields next to the trace's (fighter fields, `global.<field>`, `camera.<path>`, `ram.<address>[:<size>]`, `events`); `remake/tests/support/coverage_report.gd` checks the stages' view coverage with the traces' cameras (`godot --headless --path remake -s res://tests/support/<script>.gd -- …`).
