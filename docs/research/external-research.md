# External research and local verification

This is a source ledger for published work found while researching Tekken 3 PSX formats. An external tool or article is a lead, not evidence that a field is correct for our Japan images. Each row distinguishes the published claim from the observation made on the local discs.

| Source and claim | Local verification | Remaining limit |
|---|---|---|
| [Tek3Ex source](https://github.com/xan1242/Tek3Ex/blob/master/Tek3Ex.cpp): supported EXE has an eight-byte BNS LBA/size table and 0x800-byte bank alignment. | [`compare_bns.py`](../../tools/research/compare_bns.py) resolves and bounds all 303 records in Japan Rev.1 and USA. | The original Japan executable instead has twelve-byte rows with filename pointers; this tool's classifier is only heuristic. |
| [Tekken3Recompiled model map](https://github.com/FishB0nes98/Tekken3Recompiled/blob/main/tools/MODEL_MAP.md): 52 `3DMK` records with a fixed row table and payload boundary. | [`kmd.py`](../../tools/research/kmd.py) parses all 52 local Japan Rev.1 and USA records: 27 rows of 56 bytes, payload at 0x600, 1,043 active rows and 4,204 ordered in-bounds payload targets, 18,327 coordinate tuples, and the four 8/8/8/12-byte groups linked to exact 4/5/4/5-byte arrays in each row's third block. The original Japan index independently calls them `.kmd`. | The external map does not establish coordinate, polygon, skeleton, animation or material semantics. These byte grammars are locally verified; topology and rendered meaning still need independent checks. |
| [Sony PSY-Q Run-Time Library Reference](https://psx.arthus.net/sdk/Psy-Q/DOCS/LibRef47.pdf): `SVECTOR` is three signed 16-bit coordinates plus a reserved 16-bit word. | All 18,327 coordinate tuples parsed from local `.kmd` active rows have this width and a zero fourth word. Each enclosing block is consumed exactly by its counts and alignment. | Structural compatibility with `SVECTOR` does not establish game-space scale, skinning or which records form visible polygons. |
| [Tekken3Recompiled model map](https://github.com/FishB0nes98/Tekken3Recompiled/blob/main/tools/MODEL_MAP.md): 15 no-magic model candidates at IDs 56–70. | [`inspect_stage_tmd.py`](../../tools/research/inspect_stage_tmd.py) independently parses 36 objects, vertex ranges and packet modes in all 15 local records. Original Japan filenames are `stg_*.tmd`. | The structure differs from the generic Sony TMD envelope. Stage names and texture application still need runtime or loader evidence. |
| [Sony PSY-Q TMD file-format manual](https://psx.arthus.net/sdk/Psy-Q/DOCS/FileFormat47.pdf): polygon packet UV, CBA and TSB bitfields. | [`inspect_stage_materials.py`](../../tools/research/inspect_stage_materials.py) applies those bitfields to all 15 local stage models and same-name ARC TIMs: all 7,538 textured packets resolve to exactly one coordinate-compatible TIM in both Japan Rev.1 and USA. Thirty-nine CLUT sites differ only at unused image indices; 8,080 repeated image VRAM words have identical data. | Tekken 3's TMD envelope and vertex-index packing differ from the generic example. Cross-resource uploads, STP, color modulation and rendered orientation still need parity checks. |
| [Sony PSY-Q TIM file-format chapter](https://psx.arthus.net/sdk/Psy-Q/DOCS/FileFormat47.pdf): CLUT and pixel blocks have byte counts and VRAM rectangles; 4-/8-bit uploads pack four/two pixels per 16-bit VRAM word. | The converter (`tools/remake_import/character.py`) applies these exact packing ratios to local character ARC image rectangles and the models' UVs. It also isolates two 56-byte CLUT-only TIM-like preludes with a four-byte pixel-block length, lacking the standard image rectangle. All 24,314 group-0/1 records have vertices covered by adjacent member-0 indexed uploads. | The 56-byte object is a Tekken-specific observed variant, not a standard complete TIM. Address coverage alone does not identify the GPU page/CLUT field or prove a rendered texture. |
| [Tekken3Recompiled modding map](https://github.com/FishB0nes98/Tekken3Recompiled/blob/main/MODDING.md): 75 strict ARC records, 50 XA streams and 22 USA STR regions. | The local BNS scan gives 75 strict ARC records, exactly matching original Japan `.arc` filenames. The 50 XA descriptors and their selected sectors validate in local Japan Rev.1 and USA; USA has the reported 111,099 STR-like subheaders. | Japanese movie-region boundaries and a local STR magic/chunk/frame scan are pending. Sector counts alone cannot prove 22 regions. |
| [Tekken3Recompiled TIM tool](https://github.com/FishB0nes98/Tekken3Recompiled/blob/main/MODDING.md): standard TIMs can be scanned and exported to PNG. | The local [ARC study](formats/arc-archives.md) independently validates exact TIM sequences in character ARC member 1, most member 0 records, and named stage ARCs. | An independent PNG decode, palette/transparency comparison and rendered texture mapping remain pending. External conversion code has not been accepted as a Tekken-specific material specification. |
| [Sony PSY-Q File Formats manual](https://psx.arthus.net/sdk/Psy-Q/DOCS/FileFormat47.pdf) and [Run-Time Library Reference](https://psx.arthus.net/sdk/Psy-Q/DOCS/LibRef47.pdf): VAB header, program/tone structures and VAG size-table rule. | [`inspect_vab.py`](../../tools/research/inspect_vab.py) validates 48 local VH/VB pairs in Japan Rev.1 and USA: 72 programs, 788 tones and exact segmentation of 785 raw ADPCM samples. Three active tones have VAG ID zero. | Original playback pitch, mixing and the game's use of SEQ/SEP remain unverified. |
| [Sony Run-Time Library Overview](https://psx.arthus.net/sdk/Psy-Q/DOCS/Devrefs/Libovr.pdf): one-shot VAGs end with an extra 16-byte IRQ-clear block. [FFmpeg's PSX ADPCM decoder](https://github.com/FFmpeg/FFmpeg/blob/master/libavcodec/adpcm.c): predictor, shift, nibble order and PCM reconstruction. | All 775 local one-shot samples have Sony's exact `00 07 77…77` ending; ten others have loop markers. [`decode_vab_sample.py`](../../tools/research/decode_vab_sample.py) matches FFmpeg's PCM byte for byte on one sample of each ending type. | The source VAB does not carry a standalone sample rate; FFmpeg-equivalent PCM does not establish original SPU mixer or game playback parity. |
| [PSXPrev feature request](https://github.com/rickomax/psxprev/issues/28): Namco Tekken 1/2/3 and Soul Edge support was requested. | This is evidence of a tool-support request, not of a file layout. | Do not infer that generic TMD/HMD scanning can convert Tekken 3 `.kmd` or companion animation records. |
| [TE3MV author's development thread](https://lgt.createaforum.com/tools-58/te3mv/): reports a Tekken 3 model viewer with working texturing in 2017 and calls `3DMK` a chosen output extension. | The local original-Japan EXE instead names the 52 model records `.kmd`; the signature is `3DMK` at byte 8. All 24,314 group-0/1 records of the 52 byte-identical Japan Rev.1/USA models were found addressable inside adjacent member-0 indexed TIM upload unions. | The thread supplies no byte-level mesh grammar or reusable converter. Texture page, CLUT, geometry indices and rendered parity remain unverified. |
| [Tekken3Recomp](https://github.com/fabioap-cpu/Tekken3Recomp): a playable USA executable recompilation. | Its public description was inspected as a possible future control-flow reference. | No model, animation or effect format claim from this project has yet been checked against the Japanese discs. Playability of a recompilation does not itself document asset grammar. |
| [FF7Tools LZSS source](https://github.com/cebix/ff7tools/blob/master/ff7/lzss.py): its eight-token flag groups and two-byte references were a lead for compressed PlayStation textures. | Applying its documented eight-token, 4 KiB-window decoder to local `.tia`/`.tiz` streams produces an invalid zero-length TIM block. The local [compressed-TIM inspector](../../tools/research/inspect_compressed_tim.py) instead recovers a different seven-token, 2 KiB-distance grammar and validates all 106 TIMs in each of three releases. | The similarity of the initial `DF 10 00 00 00` bytes does not imply shared compression parameters or game code. |
| [Sony PlayStation File Formats reference](https://psx.arthus.net/sdk/Psy-Q/DOCS/Devrefs/Filefrmt.pdf): indexed TIM packing, BGR555 palette words, STP and zero-color transparency. | The [local exporter](../../tools/research/export_compressed_tim.py) applies the documented nibble/byte order to all 106 decoded TIMs, retaining the exact palette words and index raster. Every exported index PNG was reopened and matched against the TIM bytes. The first `.tiz` opaque-draw preview resolves to a character portrait. | STP's visible effect depends on runtime draw state and blend mode. The RGBA preview is not a verified frame capture. |

## Verification rules for future leads

1. Pin the source URL and exact claim. Prefer source code, format notes and SDK manuals over forum guesses.
2. Match the release by executable and track hashes or use a field-level cross-release check. Do not transfer a USA absolute address into Japan Rev.1 or the original Japanese EXE.
3. Run a bounded parser over every matching local record, including malformed or exceptional candidates. Record exact counts and counterexamples.
4. Separate structural validity from semantics: an offset that lands inside a record is not yet a vertex pointer; a TIM is not yet assigned to a fighter or screen.
5. Require a decoded/rendered or code-path comparison before writing engine conversion rules for geometry, animation, audio, text, video, or effects.
